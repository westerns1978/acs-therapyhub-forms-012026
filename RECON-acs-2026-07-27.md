## STEP 5 — RLS / 42 CFR Part 2 POSTURE

**VERDICT: The ACS-owned core tables are in decent shape — RLS ON with real staff/client-scoped policies, and determinations are append-only at the policy level. But there are two live exposures: (1) the anon key can READ AND WRITE ACS client-document metadata — including OCR-extracted document text — through a legacy `uploaded_files` policy, because ACS uploads are tagged `app_id='aiva'`; (2) the `client-documents` storage bucket is PUBLIC with anon read+upload policies still active. And the shared database carries 68 unrelated RLS-off tables (Supabase advisor: critical), which is an unacceptable neighborhood for Part 2 data with no BAA.**

### ACS client-data tables (all RLS ON, real policies — witnessed via `pg_policies`)

- `clients`, `appointments`, `form_submissions`, `clinical_notes`, `payments`, `charges`, `client_communications`, `groups`, `group_enrollments`, `assessment_inputs`, `treatment_plans`, `counselors`, `appointment_series`, `audit_logs`: staff-scoped via `private.is_staff()` / `is_clinician()`, client self-read via `private.my_client_ids()`. Client writes on `form_submissions` are blocked once status = 'reviewed'. `audit_logs` insert requires `user_id = auth.uid()` (append-only for staff).
- `placement_determinations`: SELECT (staff) + INSERT (clinician, `determined_by = auth.uid()`) **only** — no UPDATE/DELETE policy = append-only at the RLS layer. ✅
- `acs_upload_tokens`: RLS ON, **zero policies** — intentionally service-role-only via the `acs-request-upload` edge function (table comment says exactly this). ✅ by design.

### The two live exposures

1. **`uploaded_files` legacy anon policy.** Policies `uploaded_files_legacy_anon` and `uploaded_files_legacy_authenticated` grant **ALL** (select/insert/update/delete) to the `anon` and `authenticated` roles for rows where `app_id in ('aiva','acs','attesta','flowvault')`. Witnessed: ACS's live client uploads are stored with **`app_id='aiva'`** (34 rows, `bucket_id='therapyhub-patient-files'`; 29 link to real ACS `clients.id` via `hire_id`; **16 carry `extracted_text`** — OCR'd document content, plus `ocr_extracted_json`, `risk_flags`, `clinical_significance` columns). Anyone holding the anon key (it ships in the JS bundle) can read, alter, or delete this metadata without logging in. The file *bytes* are safe (private bucket, scoped storage policies) — the metadata and extracted text are not. This is the single worst Part 2 fact found today.
2. **`client-documents` storage bucket is `public: true`**, with additional explicit anon SELECT + anon INSERT policies, and it appears in an `allow_public_read` policy. It holds 10 objects (Oct–Nov 2025, folders `1/` and `2/` — AIVA-era hire docs by the naming; provenance UNKNOWN). No ACS code references this bucket ([services/storageService.ts:8](services/storageService.ts) uses only `therapyhub-patient-files`), but the bucket is live in the same project. Whether those 10 files contain PHI: UNKNOWN without opening them (not done — read-only recon and they may be another app's data).

### Storage, the good part

- `therapyhub-patient-files`: `public: false`, with `tpf_staff_all` (staff), `tpf_client_read_own` / `tpf_client_insert_own` (path-scoped to own client id), and `tpf_restrict_to_acs_scope`. ✅
- `project-acs-therapyhub`: `public: false`, 0 objects.

### The neighborhood

- Supabase's advisor flags **68 RLS-disabled tables** in this shared project (other WestFlow apps: StoryScribe, AIVA, Katie, FlowVault, etc.), fully exposed to the anon key. None of them holds ACS client rows (`documents` — RLS OFF with an unenforced policy — has 0 rows), but Part 2 data sharing a database and an anon key with this much open surface is a structural risk already tracked in the day-30 recon (shared DB, no BAA).
- The anon key **cannot** read `clients`, `clinical_notes`, `form_submissions`, `appointments`, etc. — those policies grant to `authenticated` only. The identifying leak path today is `uploaded_files` (names of files like "*_assessment.pdf" tied to client uuids, plus extracted text) and the public bucket.
